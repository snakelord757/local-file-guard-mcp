# План подключения MCP

Цель: подключить Local File Guard к локальному MCP-клиенту, проверить чтение,
маскирование и запись на синтетических данных. Регистрация сервера не выполняется
автоматически при установке проекта.

## 1. Подготовить окружение

Выполните установку из [README](README.md), скопируйте `config.example.json`
в `config.json`, загрузите модель в LM Studio и включите API на `127.0.0.1:1234`.
Задайте точный `lm_model`. При необходимости передайте `LM_STUDIO_API_KEY`
через окружение серверного процесса.

```powershell
.\.venv\Scripts\python -m gateway.doctor
```

Критерий: модель доступна и возвращает корректную JSON-классификацию.

## 2. Выбрать папки документов

По умолчанию `allowed_roots` содержит только `inbox`. Относительные пути
считаются от `config.json`; все папки должны существовать.
Для отдельной папки документов можно использовать:

```json
{
  "allowed_roots": ["D:\\DocumentsForGuard"],
  "audit_db": "data/audit.sqlite3"
}
```

Это фрагмент конфигурации: сохраните остальные поля из примера.
Не разрешайте весь диск или профиль пользователя. Файлы должны быть UTF-8
с поддерживаемым расширением и укладываться в лимиты из README.

**Аудит должен находиться вне всех `allowed_roots`.** Если разрешить весь
`D:\CodexGateaway`, стандартный `data/audit.sqlite3` окажется внутри него,
и конфигурация не пройдёт проверку. Предпочтительнее разрешать отдельную
папку документов; при необходимости доступа ко всему проекту перенесите аудит
в отдельную закрытую папку вне проекта. После изменения конфигурации
перезапустите MCP-сервер.

## 3. Зарегистрировать локальный сервер

В PowerShell из корня клона:

```powershell
$projectRoot = (Get-Location).Path
codex mcp add local-file-guard -- "$projectRoot\.venv\Scripts\python.exe" "$projectRoot\run_server.py" --config "$projectRoot\config.json"
codex mcp get local-file-guard
codex mcp list
```

Если запись уже существует, сначала проверьте её командой `get`, затем обновите
пути в настройках клиента. Для иных STDIO-клиентов адаптируйте
`mcp-client.example.json`.

Codex хранит настройки MCP в `config.toml`. Для медленной локальной модели
можно задать `tool_timeout_sec = 90` в таблице этого сервера.
Чтобы отключить сервер без удаления записи, установите `enabled = false`.
Перезапустите клиент и проверьте список активных инструментов в новом чате.
Синтаксис и параметры сверены с [официальной документацией MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
8 ноября 2026 года.

## 4. Проверить работу

Сначала запустите автоматические тесты без реальной модели:

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest -q
```

Затем, со стандартной папкой `inbox` в `allowed_roots`, выполните проверку
настоящего STDIO-процесса с LM Studio:

```powershell
.\.venv\Scripts\python -m gateway.smoke
```

В клиенте отдельно проверьте:

- Видны три инструмента: `read_safe_file`, `check_response_file`, `write_safe_file`.
- Чтение абсолютного пути к `inbox/example.txt` возвращает `redacted` и `edit_id`.
- Исходные тестовые email и ключ отсутствуют в ответе.
- На копии тестового файла изменение обычного текста с сохранением маркеров
  записывается, а исходные значения восстанавливаются только на диске.
- Запрос файла вне разрешённой папки возвращает `error`, `content: null`.

Сохраняйте резервную копию реальных документов: запись атомарна, но резервные
копии сервер не создаёт. Не прикладывайте исходные документы к чату, если
нужно сначала пропустить их через фильтр.

## 5. Диагностика и эксплуатация

| Симптом | Проверка |
| --- | --- |
| Сервер не стартует | Python, зависимости, существующие `allowed_roots`, `lm_model`, расположение аудита |
| Файл недоступен | Абсолютный путь, расширение, UTF-8, размер, отсутствие ссылок и доступ ОС |
| Ошибка модели | `gateway.doctor`, работа LM Studio, модель, тайм-аут и контекст |
| Запись отклонена | Новый `read_safe_file`, актуальный `edit_id`, каждый маркер ровно один раз |
| Инструменты после отключения остаются в чате | Перезапуск клиента и новый чат |

Определите срок хранения и права доступа для `data/`: аудит содержит разрешённый
текст и не шифруется. Тесты `gateway.verify_*` запускайте отдельно после
изучения их действий; они не заменяют проверку конкретной модели.

## 6. Удалённое подключение — отдельный этап

Облачный клиент не получает доступ к локальному STDIO через эту регистрацию.
Перед удалённым развёртыванием выберите поддерживаемый клиентом защищённый
транспорт, добавьте аутентификацию и проверьте права доступа. HTTP-режим
этого проекта слушает только loopback и предназначен для локальной работы.
Публикация репозитория на GitHub не публикует сам MCP-сервер.
