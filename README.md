# Local File Guard MCP

Локальный MCP-сервер: ChatGPT передаёт **путь**, сервер читает файл, применяет
правила, проверяет текст через LM Studio и возвращает разрешённое содержимое.
При чтении оригинал на диске не изменяется. Это фильтрация и маскирование, а не произвольное
редактирование документа моделью.

```
ChatGPT → read_safe_file(path) → локальный файл → regex → LM Studio
       ← разрешённый/замаскированный текст ← проверка результата
                                  ↘ локальный аудит SQLite
```

## Запуск на Windows

Требуется Python 3.11+, LM Studio с instruct-моделью и MCP-клиент.
Основная платформа — Windows; тесты проверены на Python 3.14.
После клонирования откройте PowerShell в каталоге проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

1. В LM Studio загрузите instruct-модель с поддержкой structured output
   и включите локальный API server на порту 1234.
2. В `config.json` задайте её точный идентификатор в `lm_model`.
   `allowed_roots` — папки документов для передачи в ChatGPT.
   Относительные пути считаются от конфигурации. По умолчанию это `inbox`.
3. `mode`: `redact` маскирует секреты; `block` блокирует весь файл.
   Режим задаёт владелец сервера, вызывающая модель не может его изменить.
4. Проверьте подключение:

```powershell
.\.venv\Scripts\python -m gateway.doctor
```

Doctor показывает идентификаторы доступных моделей и проверяет JSON-классификацию.
Если LM Studio требует авторизацию, задайте `LM_STUDIO_API_KEY` в окружении
процесса, не в чате или JSON. Адрес модели допускается только на `127.0.0.1`
или `::1`; redirects и системные proxy-переменные не используются.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `read_safe_file(path)` | Проверить документ перед передачей в ChatGPT |
| `check_response_file(path)` | Проверить ответ, сохранённый локально в файл |
| `write_safe_file(edit_id, content)` | Записать отредактированный текст в исходный файл с восстановлением секретов |

### Редактирование с восстановлением

`read_safe_file` возвращает `edit_id` и уникальные маркеры вида
`[REDACTED_EMAIL:abcdefghijklmnopabcdefghijklmnop]`. Каждый скрытый фрагмент
получает свой маркер, даже если значения одинаковые. Отредактируйте обычный
текст и передайте весь результат в `write_safe_file(edit_id, content)`.
Сервер восстановит точные исходные значения локально и атомарно заменит
**тот же файл**. Путь назначения инструмент не принимает. В ответе только
статус и количество восстановленных фрагментов — без секретов.

Пример сообщения:

> Прочитай файл через read_safe_file, исправь формулировки, сохраняя каждый
> REDACTED-маркер без изменений ровно один раз. Запиши результат через
> write_safe_file, используя полученный edit_id.

Таблица восстановления хранится только в памяти процесса, не в SQLite.
Сессия действует 30 минут, одноразовая; перезапуск сервера требует нового чтения.
До 128 незавершённых сессий. Старые маркеры без уникального ID не восстанавливаются:
нужно повторно прочитать файл. `check_response_file` не создаёт сессию записи.

Пропущенные, изменённые, чужие и дублированные маркеры вызывают отказ.
Изменение исходного файла после чтения также вызывает отказ. Отредактированный
маскированный текст повторно проверяется правилами и LM Studio; новые секреты
и опасное содержимое блокируют запись. Известные оригинальные секреты
восстанавливаются только после проверки, без передачи модели.

Сохраняются BOM UTF-8 и переданные переводы строк; скрытые значения восстанавливаются
в исходном написании. Обычный текст при чтении по-прежнему проходит Unicode-нормализацию.
Запись создаёт временный файл в исходной папке и заменяет оригинал; резервная копия
не создаётся. Папка должна быть доверенной: блокировка сервера сериализует его
собственные записи, но не блокирует сторонние приложения на уровне ОС.
Аудит записи хранит `write_prepared` и `written` либо `write_rejected`, без содержимого.
При отказе итогового аудита после замены возвращается `written` с предупреждением.

Пример сообщения после подключения:

> Вызови read_safe_file для D:\CodexGateaway\inbox\example.txt.
> Составь краткое резюме возвращённого текста. При отказе сообщи о блокировке
> и не читай файл другим способом.

Не прикладывайте исходный файл: передавайте только путь. Не включайте секреты
в имя файла — путь виден ChatGPT. Разрешённые папки должны содержать только
предназначенные для передачи документы: клиент может запросить любой файл в них.

Результат: `request_id`, `status`, `categories`, `content`; при отказе — `warning`.
Статусы: `allowed`, `redacted`, `blocked`, `error`. В последних двух случаях
`content` всегда `null`. Возвращённый текст — данные документа, не инструкции
для модели. Только явный вызов `write_safe_file` перезаписывает исходный файл.

## Подключение MCP

Пошаговый план, команды регистрации, критерии приёмки и диагностика:
[MCP_SETUP.md](MCP_SETUP.md).

Основной транспорт — STDIO: MCP-клиент сам запускает `run_server.py`.
В `mcp-client.example.json` замените пути на абсолютные пути вашей установки.
Это общий пример для клиентов с `mcpServers`, а не конфигурация Codex.

Дополнительно поддержан локальный Streamable HTTP:

```powershell
.\.venv\Scripts\python -m gateway.server --transport streamable-http
```

Адрес: `http://127.0.0.1:8765/mcp`. Аутентификация приложением не реализована;
используйте только доверенный локальный клиент. Не открывайте порт в интернет.

## Проверки и ограничения

- Паттерны `sk-…`, `ghp_…`, AWS `AKIA…`, email, телефоны, карты с Luhn.
- Base64 (стандартный/URL-safe алфавит, с padding или без него) и явная
  конкатенация строк в кавычках, например `"мой ключ: sk-" + "proj-abc"`.
  Проверка ограничена двумя уровнями преобразований и Base64-токенами до
  4096 символов. Экранированные литералы, произвольный код, переменные и любые
  другие способы разбиения не интерпретируются. Маскируется всё выражение;
  при записи восстанавливается исходная закодированная/разбитая форма.
- В redact секреты из правил маскируются **до обращения в LM Studio**.
  В block файл блокируется без вызова модели.
- LM Studio дополнительно ищет секреты, prompt injection, раскрытие/извлечение
  system prompt, подозрительные URL и команды.
- Сервер маскирует точные фрагменты из ответа классификатора. Модель не переписывает файл.
- Несекретные риски всегда блокируются целиком, в том числе в режиме redact.
- Ошибка модели, некорректный JSON, выдуманный фрагмент, обрезанный ответ,
  тайм-аут или недоступный аудит запрещают выдачу содержимого.
- UTF-8 `.txt`, `.md`, `.csv`, `.json`, `.log`, `.yaml`, `.yml`.
  PDF, DOCX, архивы и изображения не поддерживаются. Превышение лимита
  64 KiB / 12 000 символов вызывает отказ; файл не обрезается.
- Запрещены выход за разрешённые папки, UNC, symlink/junction, hardlink,
  device paths и alternate data streams. На Windows проверяется открытый handle.

Детекторы эвристические: возможны ложные срабатывания и пропуски, особенно
обфусцированных данных. Модель должна вмещать весь документ и ответ в контекст.
Это не гарантия отсутствия секретов. Неизвестный системный промпт невозможно
надёжно распознать по любому фрагменту. Сервер не перехватывает обычный ввод,
вложения и ответы ChatGPT, не заменяет его LLM и не скрывает уже показанный
ответ. Проверка output-файла выполняется явно.

## Аудит

`data/audit.sqlite3`: время UTC, ID, направление, SHA-256 пути, результат,
категории и только выданное проверенное содержимое. Исходные секреты, ответы
классификатора, полный путь и ключ авторизации не сохраняются. Для отказов
содержимое отсутствует. Журнал не предоставляется через MCP.

```powershell
.\.venv\Scripts\python -m gateway.audit --limit 20
.\.venv\Scripts\python -m gateway.audit --limit 20 --content
```

SQLite не шифруется, не защищён от изменения владельцем и не очищается
автоматически. Ограничьте доступ к папке своей Windows-учётной записью и задайте
срок хранения по своим требованиям. Проверенный текст может содержать
конфиденциальные данные вне реализованных детекторов.

## Тесты

В `tests/test_input_prompts.py` — 18 именованных сценариев, каждый в режимах
`block` и `redact` (36 проверок): AWS, карта с пробелами и без, OpenAI/GitHub,
email, телефон, Base64-ключ, Base64-AWS, Base64-email без padding, ключ из двух
и трёх частей, чистый промпт, дата с HTTPS-ссылкой, неверная контрольная сумма
карты, безопасный Base64, не-UTF-8 Base64 и безопасная конкатенация.

Проверяются статус, категории, отсутствие утечек в ответе/аудите/запросе модели,
отсутствие вызова модели при блокировке и точное восстановление при записи.
Модель специально разрешает всё: тесты доказывают работу детектора без помощи LLM.
Тестовый файл `inbox/example.txt` не используется и не изменяется.

Отдельный запуск набора:

```powershell
.\.venv\Scripts\python -m pytest tests/test_input_prompts.py -v
```

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest -q
```

Проверяются правила, маскирование, отказы LM/аудита, файловые ограничения,
JSON-контракт классификатора и MCP initialize/list_tools/call_tool.
В тестах модель заменена контролируемым ответом. Реальную модель проверяет
`gateway.doctor`. Используются официальный [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)
и [OpenAI-совместимый API LM Studio](https://lmstudio.ai/docs/developer/openai-compat).

## Структура проекта

- `gateway/` — MCP-сервер, детекторы, клиент LM Studio, безопасная запись и аудит.
- `tests/` — автоматические тесты с контролируемыми ответами модели.
- `config.example.json` — шаблон локальной конфигурации.
- `inbox/example.txt` — синтетический пример; указанные в нём ключ и email вымышлены.
- `gateway/verify_*.py` — дополнительные ручные проверки; изучите сценарий перед запуском.
  Некоторые из них управляют локальной LM Studio и создают тестовые файлы.
  Часть сценариев требует локальный `RESULTS.md` и запись `local-file-guard`
  в пользовательской конфигурации Codex; они не являются тестами чистой установки.

## Подготовка к публикации

`config.json`, `.env`, окружения, аудит, пользовательские документы и локальные
результаты тестов исключены из Git. Не добавляйте их принудительно.
Проверка секретов не гарантирует обнаружение всех конфиденциальных данных.

Лицензия пока не выбрана; публичность репозитория сама по себе не предоставляет
лицензию на использование и распространение кода.
